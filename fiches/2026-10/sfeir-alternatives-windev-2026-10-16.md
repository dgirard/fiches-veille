## Pense-betes

- **Contexte éditeur** : dongles non mis à jour depuis **février 2025**, vente par abonnement (Wx Alliance) ; facturation **à la session** au printemps 2026 (vidéo PC SOFT analysée par Louis Planquart, 30 juillet 2026).
- **Quatre critères** hérités de WinDev : tout-en-un (IHM, base, états, déploiement), productivité sur la gestion, **HFSQL** intégrée, un langage pour desktop, web et mobile. Aucune alternative ne les coche seule.
- **WinDev 2026 intègre l'IA** : complétion, compagnon IA, type WLangage `iaAgent`, `/init_project` → `companion.md`. La question devient l'écosystème et *qui en fixe le prix*.
- **Famille 1, stacks ouvertes** :
  - Java/Spring + Angular → gestion d'entreprise durable ;
  - **.NET** (C#, Blazor, WPF) → la plus proche pour une équipe Windows, runtime gratuit ; Dev-Booster : NomadBiz vers .NET + SQLite en **19 jours** ;
  - TypeScript, Python/Django, PHP, Rails → web ; Sealog : développeur WinDev produisant *« sans écrire une seule ligne de code »* avec Replit et Claude Code ;
  - **Flutter** → remplace WinDev Mobile.
  Pas de redevance, code possédé, compétences recrutables ; mais grilles, reporting et déploiement à assembler.
- **Famille 2, low-code** : adapté aux formulaires et workflows simples ; Visionsoft annonce **6 000 € HT** en quatre semaines. Réserve : recréer la dépendance ; demander comment sortir données et logique.
- **Famille 3, agents de code** : l'équipe décrit, l'agent écrit en stack ouverte, l'équipe relit. Condition : méthode (spec avant code, 11 phases, gates Define/Plan/Ship, revues parallèles).
- **Grille** : desktop Microsoft → .NET + agents ; gestion multi-techno → Java/Spring + agents ; petites apps → low-code avec stratégie de sortie ; mobile terrain → Flutter ; éditeur SaaS → stack web ouverte sur cloud managé.
- **Formation** : **50 développeurs** d'un éditeur français certifiés Claude Code en moins de deux mois par SFEIR Institute.

## RésuméDe400mots

L'article de SFEIR s'adresse aux équipes qui développent encore en WinDev et se demandent avec quel outil écrire leurs prochaines applications, question distincte du sort de l'existant traité ailleurs dans la série. Il rappelle le contexte : selon la Wx Alliance, les dongles WinDev ne sont plus mis à jour depuis février 2025 et PC SOFT vend ses outils par abonnement ; au printemps 2026, une facturation à la session s'est dessinée, détaillée par Louis Planquart. La conviction affichée est que l'AGL de 2026 est une stack ouverte pilotée par des agents de code.

L'article nomme d'abord ce que WinDev apportait : un environnement tout-en-un, une forte productivité sur les applications de gestion, la base HFSQL intégrée et un seul langage pour desktop, web et mobile. Il note que WinDev 2026 intègre lui-même de l'IA (complétion, compagnon, type iaAgent, fichier companion.md) et que la question porte donc sur l'écosystème et sur qui fixe le prix.

Trois familles d'alternatives sont examinées. Les stacks ouvertes d'abord : Java/Spring avec Angular pour les applications de gestion durables, .NET pour les équipes Windows, avec un environnement d'exécution gratuit, TypeScript, Python, PHP ou Rails pour le web, Flutter pour le mobile terrain. L'article cite Dev-Booster, qui a réécrit son logiciel vers .NET en dix-neuf jours avec l'IA tout en mettant en garde contre toute généralisation, et Sealog, qui décrit l'effet de Replit et Claude Code pour un développeur WinDev. Ces stacks n'ont pas de redevance mais obligent à reconstruire l'outillage que WinDev fournissait d'un bloc.

Le low-code vient ensuite, adapté aux applications internes simples, avec l'exemple d'un forfait de migration à 6 000 euros. SFEIR émet une réserve structurelle : une plateforme propriétaire recrée la dépendance quittée, et il faut lui demander comment sortir données et logique.

La troisième famille, les agents de code comme Claude Code, est présentée comme le changement de fond : l'équipe décrit le comportement, l'agent écrit dans une stack ouverte, l'équipe relit. La condition posée est une méthode, la Software Factory 10x de SFEIR, avec spécifications préalables, onze phases et trois validations humaines.

Une grille associe chaque situation à une alternative, de .NET pour une équipe desktop Microsoft à une stack web ouverte pour un éditeur visant le SaaS. L'article rappelle que le développeur WinDev garde sa connaissance du métier et cite la formation de cinquante développeurs à Claude Code en moins de deux mois chez un éditeur français.
