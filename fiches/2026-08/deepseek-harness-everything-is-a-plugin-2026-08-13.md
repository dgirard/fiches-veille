# deepseek-harness-everything-is-a-plugin-2026-08-13

## Veille

Page produit officielle de **DeepSeek**, publiée le **13 août 2026**, **non signée**, annonçant la mise en *developer preview* de **DeepSeek Harness** (`dsh`) — un harnais d'agent de codage **open source sous licence MIT**, dont le dépôt est ouvert le même jour. Thèse en trois mots, répétée en titre et en slogan de dépôt : ***« Everything is a plugin »***. Deuxième promesse, accolée : ***« Every run is traceable. »*** ⭐⭐ **Le sujet annoncé est la composabilité ; le vrai sujet est ailleurs, et il est double.** (1) **Ce qui distingue réellement DSH n'est pas sur la page de vente** : la composabilité par plugins est devenue banale en 2026, mais l'invariant écrit dans `docs/architecture.md` ne l'est pas — ***« Model-visible means logged. Anything that reaches a model request must be reconstructable from the log, and a runtime invariant asserts it. »*** Un harnais qui **échoue à l'exécution** si un octet atteint le modèle sans passer par le log append-only, c'est une propriété d'auditabilité qu'aucun harnais propriétaire ne peut offrir — et DeepSeek la range dans sa doc développeur, pas dans son argumentaire. (2) **Le calendrier dit le modèle d'affaires** : DSH sort le jour même où **DeepSeek-V4-Pro passe en GA**, et **trois jours avant** une nouvelle grille tarifaire API effective le **16 août 2026 à 16:00 UTC** — heures pleines / heures creuses, creux à **−50 %**, et selon la presse des tokens de sortie V4-Pro portés de ~0,87 à ~3,96 $/M en heures pleines. **Donner le harnais sous MIT, faire payer le token.** ⭐⭐ **Le démenti interne à ne pas manquer** : la traçabilité vendue en argument n°2 repose sur un log dont le dépôt écrit qu'il **n'a aucune promesse de format** — *« `dsh-session` keeps `SESSION_FORMAT_VERSION` at `0` with no compatibility promise »*, *« Backends reject old on-disk formats »*, *« **THERE WILL BE COMPATIBILITY-BREAKING CHANGES** »* (majuscules d'origine). **Une trace rejouable aujourd'hui n'est pas une archive** : au 13 août 2026, DSH offre de la *reproductibilité de session*, pas de la *conservation*. ⭐ **Ce qui, en revanche, tient à la vérification** : la promesse de substituabilité n'est pas creuse sur la couche modèle. Deux adaptateurs LLM sont livrés — `dsh-llm-deepseek` (route `deepseek-official`) et surtout **`dsh-llm-pi-ai`**, adaptateur multi-fournisseurs générique où *« un gateway OpenAI-compatible, un serveur auto-hébergé ou un fournisseur plus récent que le catalogue installé est de la configuration, pas un changement de code »*. **DSH n'est pas verrouillé sur les modèles DeepSeek**, et c'est vérifiable dans le dépôt. ⭐ **Le détail de marché le plus parlant** : le **mode Minimal** — *« two-tool coding agent with persistent bash and str_replace_editor »* — est explicitement livré *« for benchmarking models in a minimal environment »*. DeepSeek **industrialise dans son produit le harnais de mesure**, réponse directe au constat relevé dans [[zai-glm-53-emergent-cyber-2026-08-14]] (publié le lendemain) : **Claude Code était devenu le harnais d'évaluation de référence des laboratoires concurrents**. ⚠️ Et l'ironie se lit dans l'arborescence : le dépôt du rival open source de Claude Code contient un `CLAUDE.md` et un répertoire `.claude/skills`. À croiser avec [[osmani-agent-harness-engineering-2026-04-19]] et [[boeckeler-harness-engineering-coding-agents-2026-04-02]] (le harnais comme discipline), [[janakiram-agent-platform-portability-contract-2026-07-20]] (le contrat de portabilité), [[agentclientprotocol-introduction-2026-08-02]] (l'autre voie de découplage), [[google-agent-plugins-packaging-skills-mcp-2026-08-06]] (le plugin comme unité d'emballage, une semaine plus tôt) et [[mozilla-state-of-open-source-ai-2026-07]] (ce que « open source » recouvre ici).

La page met un lien « Cordis paper » au même rang que « GitHub » et « Developer docs » : **DeepSeek crédite sa dépendance en évidence plutôt que de la dissimuler**, ce qui est à porter à son crédit et constitue en même temps le point de dépendance externe du produit.

Même limite d'archivage que celle relevée pour le billet Z.ai dans [[zai-glm-53-emergent-cyber-2026-08-14]] : **ces pages d'annonce ne sont pas capturables par un `curl | lynx` ordinaire.**

## Ton

**Profil** : page de lancement produit d'un laboratoire de modèles, registre **note d'architecture abrégée** — courte (~450 mots), déclarative, sans superlatif, sans chiffre, sans concurrent nommé. Public : **développeurs de harnais**, pas utilisateurs finaux. L'adresse est explicite dès le chapeau : *« for agent harness developers worldwide »*.

**Style** : cinq traits.

1. **La thèse tient en une phrase nominale, répétée à l'identique.** *« Everything is a plugin »* est le titre H1, la description du dépôt et l'en-tête de la section design. Rien n'est argumenté : c'est **posé**, puis énuméré. La liste des capacités enfichables est elle aussi répétée mot pour mot à trois endroits — *« models, tools, skills, sessions, sandboxes, storage, loops, scheduling, and the UI »*. **La répétition littérale tient lieu de démonstration.**
2. **L'équation comme dispositif rhétorique.** *« AGENT = MODEL + HARNESS »*, en capitales, puis : *« The model is the soul of an agent. »* **Une seule métaphore dans toute la page**, et elle sert à céder le beau rôle au modèle pour mieux revendiquer le reste. Rapprocher de la formulation déjà au corpus, *modèle ~10 %, harnais ~90 %* ([[osmani-google-new-sdlc-vibe-coding-agentic-engineering-2026-05]]).
3. **L'absence totale de comparatif est en soi le message.** Aucune mention de Claude Code, Codex, Cline, OpenCode. Aucun benchmark. Aucun prix. **Un harnais qui ne se compare à rien se présente comme un substrat, pas comme un produit** — ce que confirme l'appel final, adressé non à des utilisateurs mais à des contributeurs de plugins (*« Join the DSH plugin ecosystem »*).
4. **L'aveu d'instabilité est laissé en clair, et il monte en intensité selon le support.** La page : *« remains in developer preview […] Its core plugins and APIs will continue to evolve. »* Le dépôt, en gras et en capitales : ***« THERE WILL BE COMPATIBILITY-BREAKING CHANGES. »*** **Le même fait, dit deux fois, à deux volumes.**
5. **La prose du dépôt est d'un autre registre — et bien supérieure.** *« There is no privileged core to patch »*, *« registrations are effects that unwind when their plugin unloads »*, *« Model-visible means logged »*, *« Seams are why one provider swap changes the whole product »*. **Une doc d'architecture écrite comme une doctrine, dense, sans remplissage, où chaque règle porte sa raison.** Elle contient aussi cette recommandation, qui date le document : *« We recommend using an agent to explore the codebase and understand its architecture. »*

**Formules-marqueurs** : *« Everything is a plugin »* · *« Every run is traceable »* · *« Agent = Model + Harness »* · *« The model is the soul of an agent »* · *« Every capability is a plugin that can be swapped or recomposed »* · *« select, swap, or extend any capability in configuration without changing the DeepSeek Harness source code »* · *« Everything the model sees is recorded in an append-only session log »* · *« Resume, fork, search, and replay all operate on the same event stream »* · *« There is no privileged core to patch »* (dépôt) · *« Model-visible means logged »* (dépôt) · *« THERE WILL BE COMPATIBILITY-BREAKING CHANGES »* (dépôt) · *« open-source infrastructure that is reusable and composable »*

**Position épistémique** : **acteur intéressé qui publie son code**. La page n'est vérifiable sur rien — mais elle n'affirme presque rien de vérifiable. Le déplacement à opérer est net : **cesser de juger l'annonce, aller lire le dépôt**, dont chaque affirmation d'architecture est testable. C'est le renversement que produit une publication MIT, et c'est ce qui distingue ce dossier d'une annonce de modèle.

## Pense-betes

- **⭐⭐ La vraie nouveauté n'est pas le plugin, c'est l'invariant de journalisation — et il n'est pas sur la page.** La composabilité par plugins est un lieu commun de 2026 ; la propriété que DSH énonce dans `docs/architecture.md` ne l'est pas :
  > *« **Model-visible means logged.** Anything that reaches a model request must be reconstructable from the log, and a runtime invariant asserts it. This is why a new model-visible input requires a new session event: extend `SessionEventMap` and render from the log. »*
  → **Trois conséquences, dans l'ordre de leur portée.** (1) **C'est une contrainte exécutable, pas une intention** : *un invariant runtime l'assure* — le harnais échoue si un contributeur fait passer du contexte au modèle sans l'inscrire au log. (2) **Le log devient la source, pas le compte rendu** : `deriveMessages()` **projette** l'historique modèle depuis le log ; *« Fork, resume, transcripts, telemetry, and persistence all derive from this stream. »* Il n'y a pas d'état parallèle à désynchroniser. (3) **C'est la réponse d'ingénierie à la question « qu'est-ce que l'agent a réellement vu ? »**, celle que pose tout post-mortem d'incident agentique. ⚠️ **La page vend cela sous le mot « traceable », qui est nettement plus faible** — la traçabilité est un affichage, l'invariant est une garantie. **Pour une DSI qui évalue des harnais, c'est le critère à extraire de ce dossier** : *tout ce qui atteint le modèle est-il reconstructible depuis un journal unique, et cette propriété est-elle assertée à l'exécution ?* À croiser avec l'anneau de contraintes de [[sfeir-code-review-anneau-contraintes-2026-07-30]] et l'exigence de vérificateur non complaisant de [[dumortier-marketing-ai-os-verification-2026-08-12]].

- **⭐⭐ Le démenti que le dépôt inflige à l'argument n°2 : traçable ≠ archivable.** Mis côte à côte, ces trois énoncés sont incompatibles avec l'idée d'un journal d'audit :
  | Où | Ce qui est écrit |
  |---|---|
  | Page produit | *« Every run is traceable »* — resume, fork, search, replay sur le même flux |
  | `README.md` | *« **THERE WILL BE COMPATIBILITY-BREAKING CHANGES.** »* |
  | `CLAUDE.md` | *« `dsh-session` keeps `SESSION_FORMAT_VERSION` at `0` with no compatibility promise »* ; *« Backends reject old on-disk formats »* |
  → **Ce que ça veut dire concrètement** : une session enregistrée aujourd'hui peut devenir illisible après une mise à jour, **et le backend la rejettera activement** plutôt que de tenter une migration. La posture est assumée et datée — *« Pre-release stance: foundation over blast radius. **Remove this section at the first tagged release.** With no external consumers, prefer the correct foundation over compatibility shims »*. **C'est une décision d'ingénierie défendable en préversion ; ce n'est pas une décision compatible avec l'usage qu'on est tenté de faire de l'argument « every run is traceable ».** ⚠️ **Règle pratique** : ne pas fonder de conformité, d'audit ou de rétention sur les logs DSH avant la **première release taguée** — le repère à guetter est la disparition de la section *« Pre-release stance »* du `CLAUDE.md` du dépôt, que DeepSeek désigne lui-même comme le signal. Rejoint la discipline de gouvernance discutée dans [[clinton-anthropic-secure-ai-native-sdlc-2026-07-21]].

- **⭐⭐ Le vrai modèle d'affaires est dans le calendrier, pas dans la page.** Trois dates, à trois jours d'intervalle :
  | Date | Événement |
  |---|---|
  | **13 août 2026** | **DSH publié sous MIT** + **DeepSeek-V4-Pro en GA** (`DeepSeek-V4-Pro-0813`), support natif de l'**OpenAI Responses API**, intégration optimisée pour **Codex** |
  | **16 août 2026, 16:00 UTC** | **Nouvelle grille tarifaire API** : heures pleines / heures creuses, *« Off-peak rates are 50% lower than peak »* — presse : sortie V4-Pro portée de ~0,87 à ~3,96 $/M en heures pleines |
  | **14 août 2026** | Z.ai annonce GLM-5.3 avec **le même dispositif de barème horaire** ([[zai-glm-53-emergent-cyber-2026-08-14]]) |
  → **La lecture** : **le harnais est donné, l'inférence est renchérie.** Un harnais MIT capable de router vers n'importe quel fournisseur n'a de valeur pour DeepSeek que s'il crée du volume de tokens ; il est offert comme **produit d'appel**, à l'exact opposé de la stratégie d'Anthropic (harnais propriétaire, modèle propriétaire, valeur capturée aux deux étages — cf. [[cherny-wu-reflecting-year-claude-code-2026-07-17]]). ⚠️ **Deux prudences.** (1) **Le rapport ~4,5× sur les tokens de sortie vient de la presse, pas de l'annonce API**, qui ne publie que le principe heures pleines/creuses et le −50 % ; citer le principe, vérifier le chiffre à la source tarifaire avant de le reprendre. (2) **Un barème horaire calé sur un fuseau asiatique déplace le coût réel pour une équipe européenne** — c'est le même piège que celui relevé chez Z.ai. **À vérifier avant de bâtir un budget sur les heures creuses.** Contexte de marché : [[sfeir-gpt56-sol-terra-luna-coding-agentique-pricing-2026-07-13]], [[martignole-token-manifesto-2026-07-17]].

- **⭐ « Everything is a plugin » : ce qui est vérifié, ce qui reste à vérifier.** La promesse est facile à écrire et difficile à tenir. État des lieux au 13 août, lu dans le dépôt :
  | Couche | Ce qui est livré | Verdict |
  |---|---|---|
  | **Modèles** | `dsh-llm-deepseek` (route `deepseek-official`, fetch+SSE direct) **et** `dsh-llm-pi-ai`, adaptateur **multi-fournisseurs générique** adossé à `@earendil-works/pi-ai` | ✅ **tenu** — *« un gateway OpenAI-compatible, un serveur auto-hébergé ou un fournisseur plus récent que le catalogue installé est de la configuration, pas un changement de code »* |
  | **Exécution / sandbox** | seams `ctx.fs`, `ctx.shell`, `ctx.subprocess`, `ctx.sandbox` ; POC **E2B** livré | ✅ mécanisme en place, **un** backend distant en POC |
  | **UI / distribution** | bundles `dsh-base`, `dsh-web-app`, `dsh-headless` ; profils `web` et `headless` | ✅ tenu |
  | **Boucle d'agent** | `core/agent-loop` décrit comme *« the **default** driver »* derrière l'interface `Agent` | ✅ par construction |
  | **Écosystème tiers** | topic `dsh-plugin`, page « Community plugins » | ⏳ **à observer** — un écosystème à J+0 n'existe pas |
  → **La phrase qui rend la promesse crédible** est architecturale, pas commerciale : *« **There is no privileged core to patch**: you extend dsh by mounting a plugin beside the others, and registrations are effects that unwind when their plugin unloads. »* Et son corollaire opérationnel : *« Seams are why one provider swap changes the whole product. Filesystem and subprocess providers share one execution world, so pointing them at a remote sandbox moves Bash, PTY, and LSP with them, with no provider forks. »* ⭐ **C'est le point réutilisable hors de DSH** : *une couture (seam) n'existe que si les trois rôles — Service Definition, Service Provider, Consumer — sont conçus ensemble ; « one role alone is not a seam ».* **Transposable tel quel à toute architecture d'extension.** Vérification utile pour un évaluateur : `dsh --profile web --dump-config` imprime l'arbre réellement démarré, et *« any row it prints can be replaced by a patch of your own »* — **une revendication de composabilité qui se teste en une commande.**

- **⭐ Le mode Minimal est une prise de position de marché déguisée en fonctionnalité.** Quatre modes livrés :
  | Mode | Ce que la page en dit | Ce que ça signale |
  |---|---|---|
  | **Standard** | agent de codage complet : édition de fichiers, shell, recherche fichier et web, skills, planification, goals, subagents, workflows | la parité de fonctionnalités est l'attente de base |
  | **Code** | mêmes capacités, outils exposés via le **Code Mode SDK** *« so the model can combine multi-step operations in one TypeScript program »* | convergence sur l'orchestration par code généré |
  | **Minimal** | *« Two-tool coding agent with persistent bash and str_replace_editor »* — **explicitement** *« for benchmarking models in a minimal environment »* | ⭐ **le point** |
  | **Creator** | inspection du runtime, test de plugins Cordis en mémoire, composition de nouveaux modes | l'outil de fabrication est dans le produit |
  → **Pourquoi le mode Minimal compte.** [[zai-glm-53-emergent-cyber-2026-08-14]] documentait, le lendemain, qu'un laboratoire chinois mesurait son modèle **et ceux de ses concurrents** *« in Claude Code 2.1.207 »* — le harnais d'un concurrent devenu **infrastructure de mesure partagée**. **DSH livre le harnais minimal de benchmark dans le produit, sous MIT.** Ce n'est pas une commodité pour développeurs : c'est une tentative de **reprendre la définition de la mesure**. `BENCHMARK.md` confirme l'intention en pointant la variante `jsonrpc-agent` du SDK Python. ⚠️ **La réserve honnête** : au 13 août, **aucun score n'est publié**, et rien n'indique qu'un tiers ait adopté ce harnais pour mesurer quoi que ce soit. **Une infrastructure de mesure ne se décrète pas, elle s'impose par l'usage.** Sur l'enjeu de portabilité sous-jacent : [[janakiram-agent-platform-portability-contract-2026-07-20]].

- **⭐ Le noyau du produit n'appartient pas à DeepSeek — et c'est dit en évidence.** DSH est bâti sur **Cordis** (projet `cordiverse`, indépendant), dont la conception est publiée dans un papier tiers, *A Programming Paradigm for Spatiotemporal Composability*. La page de lancement met **« Cordis paper »** au même rang de navigation que « GitHub » et « Developer docs ». Dans le dépôt, Cordis est **vendoré** — `vendor/cordis` et neuf modules frères (`cosmokit`, `hmr`, `loader`, `schemastery`, `timer`…) — avec *« manifest + sync procedure »*. → **Trois lectures, toutes défendables simultanément.** (1) **À porter au crédit** : le laboratoire cite sa dépendance plutôt que de la rebaptiser. (2) **Techniquement prudent** : le vendoring gèle la version et supprime la dépendance de disponibilité, au prix d'une procédure de synchronisation à tenir. (3) ⚠️ **Structurellement, c'est un point de dépendance externe** : l'argument central du produit — *plugins, services typés, effets réversibles, contexte partagé* — est la propriété intellectuelle d'un projet communautaire que DeepSeek ne contrôle pas. **Pour qui évalue la pérennité de DSH, la santé de `cordiverse/cordis` est une variable au moins aussi importante que celle du dépôt DeepSeek.** Angle « ce que recouvre l'open source » : [[mozilla-state-of-open-source-ai-2026-07]].

- **⭐ La Safe Use Policy dit ce que la page marketing ne dit pas — et elle est remarquablement directe.** Le lien est en pied de page, en petit. Son contenu :
  > *« Because Harness has the ability to run code and execute actions on your machine, it introduces unique security risks. Although most foundation models include **basic** safeguards against prompt injection, inherent risks remain […] **In some cases, the Agent may execute commands embedded in content, even if those commands conflict with the assigned task.** »*
  → **Un éditeur qui écrit noir sur blanc que son agent peut exécuter des instructions trouvées dans le contenu qu'il lit.** Les précautions recommandées composent une doctrine d'usage utilisable telle quelle, indépendamment de DSH : **machine virtuelle dédiée** ; **vérifier les sorties** ; **ne pas fournir d'information sensible ou confidentielle** ; **exiger une approbation humaine pour toute opération à effet significatif** ; **découper les instructions complexes en opérations isolées** — la raison donnée est bonne : *« reduce the risk that a single erroneous command affects multiple parts of the system simultaneously and facilitates the detection of abnormal behavior »* ; **n'installer que des plugins, serveurs MCP, Skills, Hooks et dépendances issus de sources fiables et revues**. ⚠️ **La dernière ligne mérite d'être relevée pour ce qu'elle contredit** : le produit dont l'argument de vente est *« tout est plugin, installez-en »* publie simultanément une politique qui dit *« n'installez que des plugins revus »*. **La surface d'attaque est proportionnelle à la composabilité vendue** — c'est le coût du modèle, il est assumé, il doit être budgété. À croiser avec [[google-agent-plugins-packaging-skills-mcp-2026-08-06]] (le plugin comme unité de distribution) et [[valente-zalewski-beyond-zero-enterprise-security-ai-era-2026-07-20]].

- **⭐ Le détail que personne ne relèvera : le dépôt du rival de Claude Code est outillé avec Claude Code.** L'arborescence racine de `deepseek-ai/deepseek-harness` contient **`CLAUDE.md`** (copie conforme d'`AGENTS.md`), **`.claude/skills`**, ainsi qu'un répertoire `.agents`. Et `docs/architecture.md` s'ouvre sur : *« We recommend using an agent to explore the codebase and understand its architecture. »* → **Ce n'est pas une anecdote, c'est la même observation que celle de la fiche GLM-5.3 vue depuis l'autre bout** : là-bas Claude Code servait de **harnais de mesure** chez un concurrent chinois ; ici il sert de **harnais de production** chez un autre. **Le produit d'Anthropic est devenu un outil de travail neutre pour ceux-là mêmes qui construisent son remplaçant.** ⚠️ **Et la conséquence pratique la plus utile** : un dépôt open source publié en 2026 par un laboratoire de pointe **documente ses conventions pour agents** (`AGENTS.md`, `CLAUDE.md`, `.claude/skills`) au même titre que pour humains (`CONTRIBUTING.md`). **C'est un standard de dépôt à copier, pas une curiosité.** Rejoint [[notion-as-code-2026-08-03]] et la logique de contexte durable de [[klaassen-thinkroom-compounding-knowledge-lifecycle-2026-07-02]].

- **⭐ La modélisation `turn` / `step` vaut d'être empruntée, quel que soit le harnais qu'on construit.** Deux définitions, brèves et non ambiguës : *« A **step** is one model request plus the tools it calls. A **turn** is zero or more steps: it opens before its first input is claimed and closes once nothing is owed. »* Le flux complet est publié (`turn/start` → `agent/pre-step` → `step/start` → `agent/request` → `llm/stream` → `tool/call*` → `tools/pre-execute|execute|post-execute` → `step/end` → `agent/turn-stopping` → `turn/end`), avec **trois domaines d'extension distingués** : *session events* (faits durables qui survivent au rechargement), *agent events* (interception du travail en vol), *capability events* (politique et adaptateurs sur une couture, *« without importing the loop »*). → **Deux détails de conception qui trahissent une vraie expérience d'exploitation.** (1) *« a rejected or empty first claim still closes a durable turn that spent no step, **so the log records the attempt** »* — **on journalise le tour qui n'a rien fait**, sans quoi le refus serait invisible au post-mortem. (2) La distinction **waterfall** (`agent/pre-step`, `agent/request`, `llm/stream`, `tools/*` — les écouteurs doivent appeler `next()` pour déléguer) **vs sérial** (`agent/turn-stopping`, sans `next()`) : **le contrat de délégation est explicite par événement**, ce qui est précisément ce qui manque à la plupart des systèmes de hooks. **Vocabulaire et taxonomie transposables à toute conception de boucle agentique**, à rapprocher de [[lushbinary-loop-engineering-ai-coding-agents-guide-2026-06-09]] et [[osmani-agent-harness-engineering-2026-04-19]].

  3. **Les tarifs ne sont pas dans l'annonce fichée.** L'annonce API du 13 août publie le **principe** heures pleines/creuses et le **−50 % hors pointe** ; les valeurs en $/M citées viennent de la presse. **Citer le principe, sourcer le chiffre ailleurs.**

## RésuméDe400mots

Page de lancement produit publiée le **13 août 2026** par **DeepSeek**, **non signée**, pour la mise en *developer preview* de **DeepSeek Harness** (`dsh`), harnais d'agent de codage **open source sous licence MIT** dont le dépôt est ouvert le même jour.

**Ce que dit la page.** Deux promesses, en quatre cents mots et sans un chiffre. **« Everything is a plugin »** : toute capacité — modèles, outils, skills, sessions, sandboxes, stockage, boucles, ordonnancement, interface — est un plugin **substituable par configuration, sans modifier le code source**. **« Every run is traceable »** : tout ce que le modèle voit est inscrit dans un **log de session append-only** — prompts système, raisonnement, appels d'outils et résultats, ordonnancement des subagents, chaque injection de contexte — et *« resume, fork, search et replay opèrent tous sur le même flux d'événements »*. Le noyau est **Cordis**, framework tiers vendoré, décrit dans un papier externe et crédité en évidence. Quatre modes d'exécution sont livrés : **Standard** (outillage complet), **Code** (outils exposés via un SDK TypeScript pour combiner plusieurs opérations en un programme), **Minimal** (deux outils, bash persistant et `str_replace_editor`, *« for benchmarking models in a minimal environment »*) et **Creator** (inspection du runtime, test de plugins en mémoire, composition de nouveaux modes). Démarrage : `npx @deepseek-ai/dsh web`.

**Ce que la page ne dit pas.** L'affirmation la plus forte est dans `docs/architecture.md` : ***« Model-visible means logged. Anything that reaches a model request must be reconstructable from the log, and a runtime invariant asserts it. »*** **Une garantie assertée à l'exécution**, pas un affichage — c'est la propriété qui distingue réellement DSH, et elle est absente de l'argumentaire. Le même dépôt en fournit le démenti : `SESSION_FORMAT_VERSION` reste à **`0` sans promesse de compatibilité**, *« backends reject old on-disk formats »*, et le README avertit en capitales qu'il y aura des ruptures. **Traçable maintenant ne veut pas dire archivable demain.**

**Le modèle d'affaires est dans le calendrier.** DSH sort le jour de la **GA de DeepSeek-V4-Pro** et **trois jours avant** une nouvelle grille tarifaire API (16 août, 16:00 UTC ; heures creuses à **−50 %**). **Harnais donné, inférence renchérie** — l'inverse exact du modèle d'Anthropic.

**Ce qui se vérifie.** La substituabilité tient au moins sur la couche modèle : outre l'adaptateur DeepSeek, **`dsh-llm-pi-ai`** rend tout gateway OpenAI-compatible accessible *« par configuration, pas par changement de code »*. Et le mode Minimal livre le **harnais de mesure** dans le produit — tentative de reprendre à Claude Code la définition du benchmark, alors même que le dépôt de DSH contient un `CLAUDE.md` et un `.claude/skills`.
