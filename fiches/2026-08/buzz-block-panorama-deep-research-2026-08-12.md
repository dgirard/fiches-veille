# buzz-block-panorama-deep-research-2026-08-12

## Veille

Rapport de recherche interne du **12 août 2026** consolidant, en vue d'une présentation, tout ce qui est publiquement documenté sur **Buzz** — le workspace humains+agents de **Block** lancé le **21 juillet 2026**, sous licence **Apache 2.0**. Il agrège les deux billets d'ingénierie déjà fichés ([[longwell-block-buzz-workspace-agents-nostr-2026-07-21]], [[patel-block-buzz-teams-tokens-benchmarks-2026-08-06]]) avec l'annonce corporate, le dépôt GitHub, la presse, X, et **trois retours d'expérience indépendants** — et c'est cette troisième couche qui porte toute la valeur ajoutée. ⭐⭐ **Le sujet annoncé est un panorama produit ; le sujet réel est un écart de vocabulaire, et le rapport le documente avec la citation qui le tranche.** Le tweet de lancement de **Jack Dorsey** annonce *« model-agnostic, decentralized, self-sovereign, and open source »* ; l'`ARCHITECTURE.md` de Block dit : ***« The relay is the single source of truth. All reads and writes flow through it. There is no peer-to-peer event exchange, no gossip, no replication. »*** Un **relais unique et autoritaire par communauté**, donc un **point de défaillance unique** — la « décentralisation » de Buzz est une **souveraineté organisationnelle** (auto-hébergement + identité portable), pas une redondance réseau. La formule de **TFTC** résume : *« Two of those three hold cleanly. The third needs a qualifier. »* ⭐⭐ **Le second écart est plus important encore pour qui évalue le produit : la rigueur est concentrée là où elle se démontre, absente là où le risque vit.** D'un côté un niveau de formalisme rare pour une **v0.4.x/0.5.x** — spécification d'isolation multi-tenant **mécanisée en TLA+**, propriétés d'autorisation vérifiées en **Tamarin**, protocole de stockage Git model-checké, journal d'audit append-only à chaîne de hash, 127 *event kinds*, NIP-01/42/98/34. De l'autre : ⚠️ **l'appartenance au canal est l'unité de permission** — *« channel membership is not fine-grained tool authorization »* (João Queirós, formule reprise partout) —, **les agents tournent en `--dangerously-skip-permissions`**, hors bac à sable, sur le poste d'un humain, et **l'observabilité manque** : *« Buzz tells me an agent got a message. It doesn't tell me what happens next »* (DevTools Daily, qui rapporte des **kills OOM silencieux**, tâches abandonnées paraissant encore actives). Block l'assume dans son propre billet mobile : *« the agent can do anything, and security rests entirely on restricting who can tell it what to do »*. **Autre limite structurante** : *tamper-evidence ≠ tamper-resistance* — les événements signés prouvent qui a fait quoi, mais **n'empêchent pas un opérateur de relais compromis de supprimer des événements** ; et sur le relais hébergé par Block, **les messages ne sont pas chiffrés de bout en bout**. **La pile technique**, absente des billets fichés : relais **Rust** (Axum WS + REST), **Postgres** (événements + recherche plein texte), **Redis** (pub/sub, présence, saisie), **S3/MinIO** (médias via Blossom), client desktop **Tauri + React**. **L'intégration agent** passe par **`buzz-acp`**, harnais **ACP** (Agent Client Protocol, né chez Zed, JSON-RPC 2.0 sur stdio) qui branche **goose, Codex, Claude Code** et **traduit ACP ↔ MCP** — ACP côté client/agent, MCP côté outils ; plus **`buzz-agent`**, agent maison (jusqu'à 8 sessions concurrentes, Anthropic Messages API / OpenRouter / tout endpoint compatible OpenAI, vLLM, llama.cpp, Ollama). ⭐ **La formule de composabilité mérite d'être retenue** : *« The agent does not know what MCP server it talks to. The MCP server does not know what agent is calling it. They compose through protocols, not imports. »* **Généalogie** : Buzz descend de **goose** (Block, 28 janvier 2025, Apache 2.0, contribué en décembre 2025 à l'**Agentic AI Foundation** de la Linux Foundation aux côtés de MCP et d'AGENTS.md ; 27 000+ étoiles) et du premier agent Slack interne de Block, **BuilderBot**, dont les problèmes de *credentials* partagés motivent l'architecture d'identité. **Réception** : ~25 900 étoiles GitHub (~7 600 en trois jours), tweet Dorsey à ~2,3-2,7 M vues, couverture TechCrunch/SiliconANGLE/Decrypt, soutien public de **Sundar Pichai**, et la formule de **Justin Waldron** — *« Buzz is not a slack killer. It's much bigger. It's the first proper multiplayer agent harness. »* ⚠️ **Le rapport se corrige lui-même sur un point qu'il faut connaître avant de citer le chiffre** : le « **+33 % de travail** » du TL;DR de Block est le **ratio de tâches terminées (20 vs 15 sur 44)**, pas un gain de score — le score passe de 59,1 % à 71,5 %, soit **+12,4 pts**. Sa section **Caveats** est explicite : benchmarks **auto-évalués par Block**, chiffres de vues issus de sources secondaires, numéro de version divergent selon la presse (v0.4.21 vs v0.4.22), tweet « yes » de Dorsey sur le BYO harnais **non vérifié par URL**. **Ironie relevée** : pour aider à quitter GitHub, Buzz héberge son code sur GitHub.

## Pense-betes

- **⭐⭐ Le désalignement à retenir, parce qu'il s'applique bien au-delà de Buzz : le vocabulaire de lancement n'est pas la documentation d'architecture.** Tweet de **Jack Dorsey** : *« model-agnostic, decentralized, self-sovereign, and open source »*. `ARCHITECTURE.md` de Block : ***« The relay is the single source of truth. All reads and writes flow through it. There is no peer-to-peer event exchange, no gossip, no replication. »*** → **un relais unique par communauté = un point de défaillance unique** ; la « décentralisation » est une **souveraineté organisationnelle** (auto-héberger + emporter son identité), pas une redondance. Verdict de TFTC : *« Two of those three hold cleanly. The third needs a qualifier. »* **Méthode transposable** : sur toute plateforme qui se dit décentralisée, aller lire `ARCHITECTURE.md` **avant** le billet d'annonce ; la contradiction, quand elle existe, est presque toujours dans le dépôt.

- **⭐⭐ L'asymétrie qui devrait décider de votre calendrier d'adoption : la rigueur est là où elle se démontre, pas là où le risque vit.** D'un côté, un formalisme rare pour une v0.x — isolation multi-tenant **mécanisée en TLA+**, propriétés d'autorisation vérifiées en **Tamarin**, stockage Git model-checké, journal d'audit append-only à chaîne de hash. De l'autre :
  - ⚠️ **l'unité de permission est l'appartenance au canal** — *« channel membership is not fine-grained tool authorization »* (João Queirós) : un agent dans un canal peut faire ce que les membres font ;
  - ⚠️ **les agents tournent en `--dangerously-skip-permissions`**, hors bac à sable, sur le poste d'un humain — Block l'écrit : *« the agent can do anything, and security rests entirely on restricting who can tell it what to do »* ;
  - ⚠️ **l'observabilité manque** : *« Buzz tells me an agent got a message. It doesn't tell me what happens next »*, avec des **kills OOM silencieux** et des tâches abandonnées qui paraissent actives (DevTools Daily).
  → **La preuve formelle porte sur l'identité et le stockage ; le risque d'exploitation est dans l'autorisation d'outil et la visibilité.** Ce sont deux choses différentes, et il ne faut pas laisser la première rassurer sur la seconde.

- **⭐ La distinction de sécurité la plus utile du dossier** : ***tamper-evidence ≠ tamper-resistance***. Les événements signés **prouvent qui a fait quoi** ; ils **n'empêchent pas** un opérateur de relais compromis de **supprimer** des événements. Ajouter : sur le **relais hébergé par Block**, les messages **ne sont pas chiffrés de bout en bout**, et les fournisseurs de modèles peuvent recevoir prompts et contenus de canal. → **Question à poser à tout fournisseur qui vend un « journal d'audit inaltérable »** : inaltérable contre la modification, ou contre la suppression ? Ce n'est presque jamais le même dispositif.

- **⭐ La correction de chiffre à faire avant de reprendre le « +33 % »**. Le TL;DR de Block annonce *« 33% more work »* : c'est le **ratio de tâches terminées — 20 contre 15 sur 44** —, **pas** un gain de score. Le score, lui, passe de **59,1 % à 71,5 %**, soit **+12,4 pts** (dont 11,4 issus des complétions supplémentaires). ⚠️ Le rapport lui-même juxtapose les deux dans sa synthèse (« 71,5 % vs 59,1 % (+33 % de travail, +12,4 pts) ») — formulation ambiguë à ne pas recopier telle quelle en slide. Détail complet dans [[patel-block-buzz-teams-tokens-benchmarks-2026-08-06]], **y compris le résultat négatif** (aucune des douze équipes ne bat le solo sur tâches courtes), qui doit accompagner le chiffre positif.

- **La pile technique, absente des billets d'ingénierie et utile pour évaluer l'auto-hébergement** : relais **Rust** (Axum WS + REST), **Postgres** (événements + recherche plein texte), **Redis** (pub/sub, présence, saisie), **S3/MinIO** (médias via Blossom), desktop **Tauri + React** ; **127 event kinds**, NIP-01 (fil), NIP-42 (auth connexion), NIP-98 (auth REST), NIP-34 (événements Git). Déploiement : Docker Compose de production (Postgres, Redis, MinIO, Caddy/TLS), Railway en un clic, ou relais hébergé gratuit de Block en beta. **Rust 1.88+, Node 24+, pnpm.**

- **⭐ L'angle interopérabilité, le plus différenciant pour une audience technique** : **`buzz-acp`** est un harnais **[[Agent-Client-Protocol]]** (né chez **Zed**, JSON-RPC 2.0 sur stdio, passé en gouvernance communautaire) qui branche **[[goose]], Codex et Claude Code**, et **traduit ACP ↔ MCP** — *ACP côté client/agent, MCP côté outils*. S'y ajoute **`buzz-agent`**, agent maison (jusqu'à **8 sessions concurrentes**, chacune avec ses propres serveurs MCP, historique et contexte ; Anthropic Messages API, OpenRouter, ou tout endpoint compatible OpenAI — vLLM, llama.cpp, Databricks, Ollama). ⭐ **La formule à garder** : *« The agent does not know what MCP server it talks to. They compose through protocols, not imports. »* → C'est **la meilleure définition en une phrase de ce que MCP et ACP achètent ensemble** ; à rapprocher de [[agentclientprotocol-introduction-2026-08-02]] et, pour le piège du sigle, de [[girard-acp-deux-protocoles-un-sigle-2026-08-02]].

- **Retours de terrain indépendants — les seules données non auto-déclarées du dossier** :
  - **DevTools Daily** (~26/07) — workspace à deux, auto-hébergé sur VPS derrière Caddy, avec Codex, Copilot et agents Claude. **Consolidation réussie** (remplace iMessage/WhatsApp/issues GitHub), **passages de main agent-à-agent réels dans un même fil**. Manque : **l'observabilité**.

## RésuméDe400mots

Rapport de recherche interne du **12 août 2026** consolidant l'état public de **Buzz**, le workspace humains+agents de **Block** lancé le **21 juillet 2026** sous **Apache 2.0**, en vue d'une présentation. Il agrège les deux billets d'ingénierie de Block, l'annonce corporate, le dépôt GitHub, la presse, X et **trois évaluations indépendantes** — cette dernière couche portant l'essentiel de la valeur ajoutée.

**Le concept.** Buzz fusionne chat d'équipe, forge Git et workflows automatisés en un seul espace où les agents sont **des membres à part entière, pas des bots**. La thèse est celle de Tyler Longwell : *« The bottleneck moved from intelligence to coordination. »* Bradley Axen (Head of AI Capabilities) en donne l'enjeu de marché : *« Every company is going to need a place where humans and agents work together. The question is whether that place is proprietary or open. »*

**L'architecture.** Relais **Rust** sur **Nostr** (NIP-01/42/98/34, 127 *event kinds*), **Postgres**, **Redis**, **S3/MinIO**, desktop **Tauri+React**. Chaque participant détient une paire de clés ; chaque message, revue, étape de workflow et événement Git est **signé** dans un journal d'audit append-only à chaîne de hash. Un formalisme rare pour une **v0.4.x/0.5.x** : isolation multi-tenant mécanisée en **TLA+**, propriétés d'autorisation vérifiées en **Tamarin**. L'intégration agent passe par **`buzz-acp`**, harnais **ACP** qui branche goose, Codex et Claude Code et **traduit ACP ↔ MCP** — *« They compose through protocols, not imports. »*

**L'écart central.** Jack Dorsey annonce *« decentralized, self-sovereign »* ; l'`ARCHITECTURE.md` de Block dit : *« The relay is the single source of truth… There is no peer-to-peer event exchange, no gossip, no replication. »* Un relais unique par communauté, donc un **point de défaillance unique** : la décentralisation est une **souveraineté organisationnelle**, pas une redondance.

**Les limites, documentées.** L'unité de permission est **l'appartenance au canal** — *« channel membership is not fine-grained tool authorization »* ; les agents tournent en **`--dangerously-skip-permissions`**, hors bac à sable ; **l'observabilité manque** (*« It doesn't tell me what happens next »*, kills OOM silencieux). Les événements signés sont *tamper-evident*, pas *tamper-resistant* : un opérateur de relais compromis peut supprimer. Sur le relais hébergé, **pas de chiffrement de bout en bout**.

**Précision de chiffre.** Le « +33 % de travail » est le **ratio de tâches terminées (20 vs 15 sur 44)**, pas un gain de score — lequel passe de 59,1 % à 71,5 %, soit **+12,4 pts**.

**Réception** : ~25 900 étoiles GitHub, tweet Dorsey à ~2,3-2,7 M vues, soutien de Sundar Pichai, et la formule de Justin Waldron : *« the first proper multiplayer agent harness »*. Caveats assumés : benchmarks **auto-évalués par Block**, aucun prix d'hébergement, aucun chiffre d'adoption.
